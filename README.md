# Astro Starter Kit: Minimal

```sh
pnpm create astro@latest -- --template minimal
```

> 🧑‍🚀 **Seasoned astronaut?** Delete this file. Have fun!

## 🚀 Project Structure

Inside of your Astro project, you'll see the following folders and files:

```text
/
├── public/
├── src/
│   └── pages/
│       └── index.astro
└── package.json
```

Astro looks for `.astro` or `.md` files in the `src/pages/` directory. Each page is exposed as a route based on its file name.

There's nothing special about `src/components/`, but that's where we like to put any Astro/React/Vue/Svelte/Preact components.

Any static assets, like images, can be placed in the `public/` directory.

## 🧞 Commands

All commands are run from the root of the project, from a terminal:

| Command | Action |
| :------------------------ | :----------------------------------------------- |
| `pnpm install` | Installs dependencies |
| `pnpm dev` | Starts local dev server at `localhost:4321` |
| `pnpm build` | Build your production site to `./dist/` |
| `pnpm preview` | Preview your build locally, before deploying |
| `pnpm astro ...` | Run CLI commands like `astro add`, `astro check` |
| `pnpm astro -- --help` | Get help using the Astro CLI |
| `pnpm deploy` | **Deploy to Cloudflare Workers** |

## 🌍 Cloudflare Workers Deployment

This project is configured for **Cloudflare Workers** using the `@astrojs/cloudflare` adapter.

### Prerequisites

- A [Cloudflare account](https://dash.cloudflare.com/sign-up) (free tier available)
- [Wrangler CLI](https://developers.cloudflare.com/workers/wrangler/install-and-update/) installed
- [Node.js](https://nodejs.org/) v18+ (recommended: v22+)

### Configuration Files

| File | Purpose | Documentation |
|------|---------|---------------|
| `astro.config.mjs` | Astro configuration with Cloudflare adapter | [Astro Cloudflare Adapter](https://docs.astro.build/en/guides/integrations-guide/cloudflare/) |
| `wrangler.jsonc` | Cloudflare Workers configuration | [Wrangler Configuration](https://developers.cloudflare.com/workers/wrangler/configuration/) |
| `pnpm-workspace.yaml` | pnpm build permissions | [pnpm Configuration](https://pnpm.io/pnpm-workspace_yaml) |
| `package.json` | Project dependencies and scripts | - |

### Key Configuration Details

#### `astro.config.mjs`
```javascript
import { defineConfig } from "astro/config";
import preact from "@astrojs/preact";
import cloudflare from "@astrojs/cloudflare";

export default defineConfig({
  site: "https://example.com",
  output: 'server',        // Required for SSR/on-demand rendering
  integrations: [preact()],
  adapter: cloudflare({
    mode: 'standalone'    // Required for Cloudflare Workers
  })
});
```

**Why `output: 'server'`?**
- Enables **Server-Side Rendering (SSR)** and **on-demand rendering**
- Required for Cloudflare Workers deployment
- Without this, Astro generates only static files (not compatible with Workers)

**Why `mode: 'standalone'`?**
- Generates a single Worker that handles all routes
- Alternative: `mode: 'directory'` for Workers Static Assets
- See: [Cloudflare Adapter Modes](https://docs.astro.build/en/guides/integrations-guide/cloudflare/#mode)

#### `wrangler.jsonc`
```json
{
  "name": "astro-test",
  "compatibility_date": "2026-09-17",
  "compatibility_flags": [
    "nodejs_compat",
    "global_fetch_strictly_public"
  ],
  "main": "@astrojs/cloudflare/entrypoints/server",
  "assets": {
    "directory": "./dist",
    "binding": "ASSETS"
  },
  "observability": {
    "enabled": true
  }
}
```

**Key fields:**
- `name`: Your Worker's name (must be unique per account)
- `compatibility_date`: Date for runtime compatibility (use today's date)
- `compatibility_flags`: Required for Node.js API compatibility
- `main`: Entry point generated by `@astrojs/cloudflare`
- `assets.binding`: Required for static assets handling

#### `pnpm-workspace.yaml`
```yaml
allowBuilds:
  esbuild: true
  sharp: true
  workerd: true  # Required for Cloudflare Workers runtime
```

**Why `workerd: true`?**
- `workerd` is the Cloudflare Workers runtime (native binary)
- pnpm blocks build scripts by default for security
- This explicitly allows the `workerd` package to run its postinstall scripts
- See: [pnpm Supply Chain Security](https://pnpm.io/blog/2023-09-04-supply-chain-security)

### Deployment Steps

#### 1. Install Dependencies
```bash
pnpm install
```

#### 2. Authenticate with Cloudflare
```bash
# Login to Cloudflare (opens browser)
npx wrangler login

# Or use API token
npx wrangler login --api-key YOUR_API_KEY
```

#### 3. Build and Deploy
```bash
# Build your Astro site
pnpm build

# Deploy to Cloudflare Workers
pnpm deploy
```

Or in one command:
```bash
pnpm run build && wrangler deploy
```

#### 4. Update DNS (Optional)
After deployment, Wrangler will provide a `*.workers.dev` URL.
To use your custom domain, configure routes in Cloudflare dashboard.

### Local Development

#### Preview with Wrangler
```bash
pnpm run wrangler-preview
```

This starts a local development server that simulates the Cloudflare Workers environment.

#### Debugging
```bash
# Generate TypeScript types for bindings
pnpm run generate-types

# View Wrangler logs
npx wrangler logs --tail
```

## 🔧 Troubleshooting

### Error: `ERR_PNPM_IGNORED_BUILDS`
**Cause:** pnpm blocks `workerd` build scripts for security.

**Solution:** Add to `pnpm-workspace.yaml`:
```yaml
allowBuilds:
  workerd: true
```

Or run:
```bash
pnpm approve-builds
```

**Documentation:** [pnpm Supply Chain Security](https://pnpm.io/blog/2023-09-04-supply-chain-security)

---

### Error: `No 'name' field provided in wrangler.jsonc`
**Cause:** Missing or invalid `wrangler.jsonc` configuration.

**Solution:** Ensure `wrangler.jsonc` exists with a valid `name` field:
```json
{
  "name": "your-worker-name",
  "main": "@astrojs/cloudflare/entrypoints/server",
  "compatibility_date": "2026-09-17"
}
```

**Documentation:** [Wrangler Configuration](https://developers.cloudflare.com/workers/wrangler/configuration/)

---

### Error: `Could not resolve "XXXX"`
**Cause:** Using Node.js runtime APIs not available in Cloudflare Workers.

**Solution:** 
- Use Cloudflare-compatible alternatives
- Check [Cloudflare Node.js Compatibility](https://developers.cloudflare.com/workers/runtime-apis/nodejs/)
- Add `nodejs_compat` to `compatibility_flags` in `wrangler.jsonc`

**Documentation:** [Node.js Compatibility](https://developers.cloudflare.com/workers/runtime-apis/nodejs/)
